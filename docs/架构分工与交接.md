# 架构分工与交接

## 当前形态

已经按“一个项目、两个维护区”拆分，不是需要单独启动的插件服务。AI 可通过数据和能力 interface 独立离线测试，平台通过 Adapter 使用它；保持一套数据库、一个后端进程、统一 start.bat。

| 目录 | 主维护方 | 责任 |
| --- | --- | --- |
| ai_component/ | AI 开发方 | 模型、提示词、Agent、有限修复、独立审核、核心测试 |
| backend/app/routers/ | 平台开发方 | HTTP、权限、上传、发布、学生与教师业务流程 |
| backend/app/domain/ | 平台开发方 | 商科规则、确定性财务计算、业务校验、学生可见策略 |
| backend/app/integrations/ai/ | 平台开发方，双方联调 | 任务恢复、授权证据、制品存储、外部检索、接纳候选稿 |
| frontend/src/features/ai/ | 平台开发方，双方联调 | 集中的 AI 交互与 AI 请求 |
| frontend/src/pages/、layouts/、api/ | 平台开发方 | 页面、导航、账号、案例、推演、同源传输 |
| contracts/ | 双方 | 数据、能力、错误、动态复盘完整性、引用和日志约定 |

AiTask/AiArtifact 与 Case/Review 的 ORM 定义仍在平台 models.py，避免迁移表或重复注册；Review 是业务报告，不归模型直接管理。通用文档解析和账号实现保留在 backend/app/services/。

## 调用关系

业务路由 → integrations/ai（授权与数据投影）→ ai_component → 模型。
AI 的受限工具回调 → integrations/ai → 当前会话快照/已提交结果。
确定性推演 → domain → 教师发布快照，不调用模型。

AI 不导入 backend/ORM/路由，不自行选择学生、SQL 或文件路径。业务校验传给案例生成器；AI 候选内容经校验才保存。教师复盘修改优先；案例生成期间如版本被教师更新，旧候选仅保留为制品，不覆盖教师内容。

制品元数据与权限留在 ArtifactStore；二进制读写通过 BlobStorage 的 put/read interface，当前 LocalBlobStorage 保持旧路径，测试 MemoryStorage 验证替换。未来 OSS Adapter 返回对象定位符即可，需另行迁移历史定位符；本轮没有接入 OSS 或搬移文件。

## 文件迁移地图

- services/llm、generator、student_agent → ai_component/providers、agents。
- services/tutor_agent → AI 规划/回答在 agents，会话读取/检索/归档在 integrations/ai/tutor.py。
- services/task_runner、artifacts → integrations/ai；workflow 拆为 AI 生成修复与平台校验落库。
- app/rules、services/financials、validator、decision_engine → domain。
- services/review_contract → domain 绑定教学规则 + contracts/review 共享完整性算法。
- 旧自由决策模型估算和稳健降级路径删除；正式推演行为不变。
- 助教、复盘、AI 建议、生成表单、任务展示移到 frontend/src/features/ai。
- 通用 Axios 配置在 frontend/src/api/transport.ts，业务请求在 client.ts，AI 请求在 features/ai/api.ts。

旧 Python 内部 import 路径不提供兼容壳；测试已改到实际执行位置，避免 mock 失效后误用真实模型。外部 HTTP 路径不变。

## 启动与数据

继续从项目根双击或运行 start.bat；保留实时日志窗口。依赖已安装时只检查，前端仍会构建。
也可从项目根执行 .\.venv\Scripts\python.exe -u scripts\run_server.py。
手动 Uvicorn 从根使用 python -m uvicorn backend.app.main:app；如当前在 backend，使用 --app-dir ..，不要再混用 app.main。

保持原位置：backend/.env、backend/data/app.db、backend/data/artifacts、backend/app/static/qrcode、logs、frontend/dist。制品历史相对路径仍以 backend 为锚；未移动运行数据。模型由本机 .env 的 LLM_* 决定，云端数据库与对象存储迁移不在本次范围。

## 交给搭档

交付整个项目的源码与模板，不是只复制 backend。必须包含 ai_component、contracts、backend、frontend、docs（包括商科规则与标杆案例 JSON）、scripts、start.bat、README、依赖清单和前端锁文件。

不要交付真实 .env、.venv、node_modules、backend/data、二维码产物、logs、__pycache__、.pytest*、frontend/dist。搭档在自己电脑创建 .env、虚拟环境和依赖，不要复制你的 Python 启动器。历史数据迁移另做授权备份。

## 联合验收

从根目录，设置测试 DATABASE_URL=sqlite:///:memory: 后：

    .\.venv\Scripts\python.exe -m pytest backend/tests ai_component/tests -q -p no:cacheprovider

前端目录：

    npm.cmd test
    npm.cmd run build

真实 HTTP 离线联调：一个终端在根运行 python -m backend.tests.student_ui_server（只监听 127.0.0.1:8198、临时数据库、Mock AI）；另一个运行 python -m backend.tests.architecture_http_smoke，完成后 Ctrl+C 关闭测试服务器。不要把测试入口用于部署。

推荐自动方式：在项目根运行 .\.venv\Scripts\python.exe scripts/verify_http.py，自动选取本机空闲端口、启动临时 Mock 服务、验证并关闭自己创建的进程。

验收关注：无模型时已发布案例仍可推演；授权证据不泄露未选结果；动态复盘与中文引用；任务幂等、重启恢复、制品追溯；教师修改不被覆盖；已发布列表、令牌和二维码入口保持可用。核心/架构测试还阻止 AI 再依赖业务 ORM 和路由。
