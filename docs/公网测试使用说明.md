# 公网测试：本机运行、密钥隔离

## 启动与发给测试人员的内容

1. 双击项目根目录的 `start-public.bat`。首次运行时自动创建本机 `.venv`、安装缺失的 Python/npm 依赖并构建前端；后续检查到依赖已齐时跳过下载。它启动五个独立空间和 HTTPS 隧道，不运行示例数据初始化，也不要求先启动 `start.bat`。
2. 启动窗口显示 Teacher、Student 两个网址。相同网址也保存在 `private/public-test/links.json`。
3. 五个长期密钥保存在 **`private/public-test/access-keys.json`**。从文件取一个密钥，连同两个网址单独发给对应测试人员，不要把整个文件群发。
4. 教师打开教师网址，输入密钥后直接进入工作台。学生打开学生网址，先输入同一密钥，再注册/登录个人学生账号，供教师区分作答者。

同一密钥可以由一组测试人员使用：教师发布的案例会显示在这个空间的学生案例列表。不同密钥的案例、账号、文件、任务、复盘完全隔离。

测试密钥同时授权教师与学生两种入口，**不是教师/学生权限分离系统**。只发给受信任的测试人员；暂不用于正式课堂或真实敏感信息。

## 网址、密钥和数据各自的有效期

- 默认 Quick Tunnel 公网地址由 Cloudflare 临时生成，每次重启都可能变化；请以启动窗口打印的地址或 `private/public-test/links.json` 为准，旧链接不能保证继续可用。
- 如需重启后 URL 不变，请配置 Cloudflare Named Tunnel 和一个已接入 Cloudflare DNS 的域名/subdomain（没有这项前置时无法保证固定网址）。在 Cloudflare 控制台创建 remotely-managed tunnel，添加 Published application，将稳定 hostname 指向 `http://localhost:8200`，取得 tunnel token 并保存至 `private/public-test/cloudflared-token.txt`（此文件已被 Git 忽略；不要提交或转发）。然后运行：`powershell -ExecutionPolicy Bypass -File scripts/run_public.ps1 -NamedTunnel -PublicHostname case.example.com`。启动器会等待 Cloudflare 注册连接后才写出固定链接；缺 token、hostname 或路由时会明确报错。也可设置 `CLOUDFLARE_TUNNEL_TOKEN_FILE` 与 `PUBLIC_HOSTNAME` 环境变量。Cloudflare 官方说明：[Named tunnel token 参数](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/run-parameters/)、[发布应用路由](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/)。
- 密钥没有过期时间，启动不会重新生成或替换已有密钥。
- 每个空间的数据保存在 `private/public-test/spaces/test-N/`；重启后继续存在，不会每次清空。
- 第一次启动不复制本地案例、账号、文件，也不创建演示案例；教师上传后才产生案例。
- 删除 `access-keys.json` 中对应的整个对象，即撤销该密钥。每次请求都重新校验，已登录浏览器也会被拒绝；无需重启。不要只删除 key 字段而留下无效对象。
- 删除密钥不删除对应数据。以后恢复相同 id 的密钥仍会访问该 id 的历史数据；想要新空间应使用新的 id，并重启启动器。
- 若配置 JSON 格式错误，系统拒绝所有业务访问，不会退回本地数据库。
- 切换空间访问 `/access/logout` 后输入另一密钥；不同空间的教师/学生令牌不会通用。若一个浏览器要同时测试多个空间，请使用不同浏览器配置或无痕窗口。

## 关闭与日志

公网窗口必须保持运行，电脑保持联网且不要睡眠。按 Ctrl+C、关闭启动窗口，或双击 `stop-public.bat`，即可停止公网入口；Windows Job Object 确保强行关闭启动器也会清理它的子进程。停止脚本只匹配本项目的正式公网启动器，不关闭普通本地服务。再次访问将失败，但已保存的数据和密钥保留。

启动窗口汇总显示各空间的日志，带 `[test-1]` 等前缀。完整记录：

- `private/public-test/spaces/test-N/runtime.log`：上传、AI 阶段、业务报错。
- `private/public-test/spaces/test-N/process.log`：后端启动与进程报错。
- `private/public-test/tunnel.log`：公网连接状态。

原 `start.bat` 仍是普通本地开发入口，原数据库 `backend/data/app.db` 保持不变，**不会通过这条公网隧道暴露**。公网启动器只监听本机回环地址，隧道只代理受密钥保护的网关。

## AI、上传、二维码与网络条件

AI 继续读取本机 `backend/.env` 的模型配置，密钥不会发到浏览器。测试人员实际使用 AI 会消耗你的模型账户额度。请自行关注额度，结束测试及时关闭程序。

上传上限为每个请求 30 MB。公网二维码使用当前 HTTPS 地址；隧道重启变更网址后需重新发布/获取二维码。二维码不包含测试密钥，扫码者仍须登录同一空间。

Quick Tunnel 不支持标准 SSE，因此网关为助教保留相同消息格式、改用 fetch 分块文本响应，并发送等待心跳。前端无须单独配置公网 API 地址。

这是开发测试隧道，不是保证可用性的生产托管。不同测试者所在网络可能无法连接 Cloudflare；需要他们实际打开链接确认。固定域名、高可用和正式部署应另行配置具名隧道/云服务器。

官方说明：https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/

`tools/cloudflared.exe` 来自官方 GitHub Releases 的 Windows amd64 版本；若文件缺失，从 https://github.com/cloudflare/cloudflared/releases 下载并放到该位置。

## 维护边界与验证

- `scripts/run_public.py`：进程、独立数据库/文件目录、隧道生命周期。
- `scripts/public_gateway.py`：密钥校验、撤销、空间路由、响应适配。
- `scripts/process_group.py`：Windows 进程树随窗口退出。
- 原 AI 组件无需知道测试空间，仍由各自后端提供数据库与文件上下文。
- `private/` 和隧道程序已加入 Git 忽略，不要把密钥配置、测试数据库和日志打包进源码交接包。

可随时运行 `scripts/check_public.py --url <公网地址> --config private/public-test/access-keys.json` 验证五个入口（用项目虚拟环境的 Python）。脚本只登录、读取，不创建案例/账号、不调用模型、不打印密钥；默认允许已有案例和学生记录。只有需要验收全新空空间时再添加 `--require-empty`。
