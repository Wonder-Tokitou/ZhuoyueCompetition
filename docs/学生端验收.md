# 学生端改造与验收

## 职责

- `/student` 长期开放，不依赖某个案例令牌。粘贴链接/令牌进入案例，支持原生二维码检测的浏览器还可在页面内扫描或选图识别。不支持时明确提示使用手机相机或粘贴链接；局域网普通 HTTP 无相机权限时建议使用 HTTPS。
- 学生选项隐藏风险词，打乱后按页面顺序显示 A/B/C，提交时保留原策略 key。每个会话顺序固定，刷新不变；后续新会话可能不同。
- 决策阶段不调用模型。文字是决策理由，不产生新财务估算。指标与摘要严格读取当前会话冻结的教师确认结果，后端只计算前后差值。
- 答疑 Agent 规划受限只读工具，读取当前会话的文件快照、当前节点、已提交结果及规则；不能自由访问文件系统，不能读取未选答案。回答附可追溯来源，仍需教师监督其专业性，引用验证不等于绝对无幻觉。
- 完成三个节点后异步生成复盘：原素材/教师版本/实际选择 → 生成 → 完整性检查 → 独立AI语义审核 → 修复 → 存储。分析项数量和顺序动态保留，必须覆盖基础框架内容并有独立结论；教师记录页可查看。失败可重试，不下线已发布案例，不覆盖人工复盘。

## 接口增量

- `POST /api/play/{token}/sessions`：姓名初始化与冻结教师版本。
- `GET /api/play/{token}/sessions/{id}`：恢复进度，仅提供题面和已提交结果。
- 原 decide 接口必须提供 `option_key`，可同时带 `input_text` 决策理由；纯文字测算明确拒绝。
- 原 chat 接口保持 SSE 容器，Agent 完成检索及引用校验后发送答案，不再直接透传模型未经检查的字符流。
- 原 review 接口增加阶段/尝试次数；`POST /api/play/{token}/review/retry?session_id=` 重试失败任务。
- 教师 records 增加 session_id、review_id、review_status 和 review 正文。
