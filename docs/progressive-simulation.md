# 递进推演 v1

本机制在业务后端 `backend/app/domain/progressive.py` 中计算，不调用模型。
教师规则通过 `services/simulation.py`、教师接口与校准页的 `ProgressivePanel.tsx` 联动。
AI 组件仍只负责生成内容、答疑与复盘；不得写入教师规则。

## 教师操作

1. 保存案例基准，确认营收、毛利率、营业成本、运营费用口径一致。
2. 节点生成完成后，在“递进推演”中填写本期现金净流量（万元）。不从原文字推测金额。
3. 核对9个选项的营收%、毛利率百分点、费用%、现金流%、份额百分点变化。默认0代表无影响，不是模型建议。
4. 预览27条完整路径（展开可看各轮），勾选确认，保存规则，再发布案例。
5. 修改基准或规则后重新预览并发布，只有新推演采用新发布版本。

## 计算规则

- 营收 = 前轮营收 × (1 + 营收变化% / 100)。费用、现金净流量同理。
- 毛利率 = 前轮毛利率 + 本轮百分点变化。市场份额同理。
- 营业成本 = 本轮营收 × (1 − 本轮毛利率 / 100)。
- 净利润 = 本轮营收 − 本轮营业成本 − 本轮运营费用。
- 金额每轮按四舍五入保留两位小数，毛利率及份额保留一位小数，后轮用已保存金额计算。
- 现金净流量不是余额；负值×增长比例代表流出扩大，0乘比例仍为0。
- 所有27条路径均须满足有限金额、毛利率和份额在0—100%内；不静默裁剪不合理结果。
- 现有选项绝对值仅用于旧模式；递进模式以本轮实际计算结果为准，不混用旧摘要。

## 版本与兼容

新增 `simulation_config` 表保存教师草稿与最后发布的完整案例快照，无需改写既有表结构。
首次升级不自动启用，不更改原案例和学生记录。保存规则不等于发布。
已开始/已完成的 session 使用自己的 `case_snapshot_json`；没有 simulation 字段的记录继续旧预设结果。
主动“覆盖重做”属于新推演，使用最新发布版本；回退上一轮仍用该会话原版本。
重新生成节点后，节点ID与规则不匹配会拒绝发布，需教师重新核对9条规则。
财务状态保存在原有 JSON 字段，并通过 `financial_state` 返回金额字段，旧四指标接口保持兼容。
服务重启不会丢失教师规则或学生状态。AI复盘读取实际各轮数据；助教只读已选规则和结果。

## 部署

先备份代码、前端构建及SQLite数据库，隔离数据库回归测试通过后部署。
应用 `create_all` 自动创建新表；回滚代码时可保留新增表，不删除业务数据。
不可把旧代码运行后的递进会话当旧固定结果继续提交，因此出现部署异常应立即回滚到切换前并核查新增会话。
