# 5 分钟路演与问答脚本

## 路演

**0:00—0:40｜痛点**  
传统案例课堂常停留在静态选择题：教师准备材料成本高，学生每轮决策之间缺少状态延续，结果与复盘难以追溯。

**0:40—1:20｜产品闭环**  
case-sim 提供教师登录、素材输入、外部 AI 任务协作、人工校准、硬校验发布、学生三轮推演、复盘和记录查看。AI 负责辅助生成，教师保留最终控制权。

**1:20—2:10｜核心技术**  
系统采用 React 与 FastAPI，SQLite 固定 8 张业务表。每次尝试创建 session，冻结案例版本与题面快照；每个 turn 保存 before、after、delta 和来源。这样教师修改新版案例时，进行中的学生题目不会变化。

**2:10—3:00｜安全与可信**  
学生首屏只收到选项 key 和 label，不提前获得风险、摘要或指标。发布前强制校验三节点、九选项、三档风险、摘要和四指标。学生决策阶段不调用模型：自定义决策只作为「决策理由」保存，前后指标差值由后端确定性计算，不中断演示，也不把原始基准值伪装成计算结果。

**3:00—4:10｜现场演示**  
教师登录并打开案例，展示背景/困境编辑和发布校验。学生端用虚构昵称进入，完成预设选择与自由输入，观察指标连续变化；第三轮后打开复盘。教师端查看记录。

**4:10—4:40｜验证结果**  
后端与 AI 指标 132 passed（前端 34 passed，TypeScript + Vite 构建通过）。教师端、学生端、390px 移动宽度和局域网访问已人工验证。全新 Windows 一键启动（需在干净 Windows 主机运行 `start.bat` 实测）与公网压力测试（需公网环境部署后压测）仍为未验证。

**4:40—5:00｜结尾**  
“我们的重点不是替代教师，而是让案例制作更高效、推演状态可追溯、复盘有依据。下一步将根据真实课堂反馈决定是否扩展学生自建案例试跑。”

## 问答准备

**Q：AI 会不会编造结果？**  
A：外部 AI 结果要经过结构和行业边界校验，并由教师在发布前人工审核。学生决策阶段不调用模型，前后指标差值由后端确定性计算，不存在「模型失败降级」路径。

**Q：为什么只用 SQLite？**  
A：当前是初赛 MVP，单机零运维更适合现场演示。大规模并发性能未验证（需公网环境压测），不作超出事实的承诺。

**Q：教师修改案例会影响正在答题的学生吗？**  
A：不会。session 创建时冻结案例版本和完整快照，新 session 才读取新版本。

**Q：如何避免提前泄露答案？**  
A：S1 只返回题面和 `{key,label}`；风险、摘要、指标只在学生提交对应选项后返回。

**Q：是否有微信小程序？**  
A：没有。当前是移动优先 Web 页面，已验证 390px 尺寸和局域网访问，不宣称微信原生实现。

**Q：数据是否包含真实学生隐私？**  
A：演示要求使用昵称或虚构姓名，不收集学号和手机号；正式部署前仍需按学校制度补充隐私告知与数据治理。

**Q：测试情况如何？**  
A：当前记录为后端与 AI 指标 132 passed、前端 34 passed、TypeScript + Vite 构建通过，并完成人工主流程验收；全新主机启动（需在干净 Windows 主机运行 `start.bat` 实测）和压力测试（需公网环境压测）未验证。
